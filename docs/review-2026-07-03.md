# Review PocketCli - 2026-07-03

## O que o PocketCli e

PocketCli e um cliente operacional leve para administrar maquinas por SSH/Tailscale, pensado para rodar bem em terminal limitado, especialmente iPad com iSH. Ele resolve tres dores principais:

- acesso remoto rapido com menu/TUI, tmux e hosts salvos;
- execucao remota com safety, approvals, ledger e auditoria local;
- ambiente portatil que instala dependencias, preserva `profile/` e consegue operar mesmo quando Tailscale CLI/daemon nao esta disponivel.

Como ele faz isso hoje:

- shell POSIX para bootstrap, instalacao, update, menu, runtime de sessao, Tailscale fallback e wrappers SSH;
- Go para comandos estruturados (`pocket exec`, `fleet`, `ledger`, `capabilities`, `connect`, memoria/contexto/insights);
- arquivos locais em `~/.config/pocketcli`, `~/.local/share/pocketcli`, `~/.cache/pocketcli` e codigo instalado em `~/.pocketcli`;
- safety via allow/blocklist, envelopes de aprovacao, tokens temporarios, auditoria JSONL e ledger pesquisavel.

## Metricas para considerar bom

Estas metas devem virar budget de CI/smoke conforme o projeto amadurecer:

| Area | Meta |
|---|---:|
| `pocket help` shell/Go | ate 150 ms em mac/Linux, ate 500 ms em iSH |
| `pocket capabilities --json` | ate 250 ms sem rede; arquivo gerado ate 64 KiB |
| primeiro render do menu | ate 700 ms com Tailscale indisponivel; ate 1500 ms em iSH |
| menu idle | CPU media abaixo de 2%; nenhuma chamada de rede em loop menor que 15 s |
| `pocket resume` com sessao existente | ate 300 ms para anexar |
| `pocket resume` recriando tmux | ate 1000 ms fora custo do tmux |
| `pocket hosts --json` fallback salvo | ate 500 ms |
| `tailscale status --json` no inventario | timeout maximo 8 s, sem travar menu |
| `pocket connect <host>` resolve | Tailscale em ate 5 s; fallback DNS quando CLI falha |
| approval interativo | timeout padrao 30 s, sem goroutine/processo preso |
| `pocket exec` overhead local | ate 250 ms antes de probe/SSH |
| `pocket exec` output | truncar stdout/stderr em 64 KiB por stream |
| `fleet plan` ate 200 hosts | ate 500 ms com inventario local |
| `fleet exec` concorrencia | max 16 hosts simultaneos |
| `ledger search --limit 50` | ate 500 ms com 10k eventos recentes |
| Skill Layer request valido | schema + guard rails ate 150 ms antes do Ansible |
| update com diferencas locais | preservar `profile/`; falhar sem perder stash temporario |

## Escala de criticidade

- 0: observacao sem impacto imediato.
- 1: limpeza, UX pequena ou ruido de ferramenta.
- 2: bug menor, falso positivo ou degradacao contornavel.
- 3: bug real de UX/seguranca/performance sem perda critica.
- 4: risco alto de seguranca/operacao, precisa desenho e PR dedicado.
- 5: critico, pode vazar segredo, executar destrutivo sem barreira ou quebrar update de forma irreversivel.
